# 隊列メーカー 仕様メモ

この文書は、隊列表作成アプリ「隊列メーカー」の現在仕様と今後の実装方針をまとめるものです。
Codex は実装前に `AGENTS.md` とあわせて参照してください。

## 1. アプリ概要

隊列メーカーは、ダンス、舞台、パレードなどで使う隊列表を作成・編集・保存・印刷・書き出しできるWebアプリです。

主な用途:

- ダンスステージのシーンごとの隊列表作成
- 舞台演出でのメンバー・道具・幕の配置管理
- パレード形式の縦長隊列作成
- メンバーや道具の表示・非表示管理
- 道具割当の管理
- 印刷、PDF保存、スクリーンショット、ZIP共有

## 2. 技術構成

- React
- TypeScript
- Vite
- Tauri（Windowsダウンロード版）
- npm

主なディレクトリ:

- `src/App.tsx`: アプリ全体の状態管理・画面構成の中心
- `src/components/`: パネル、キャンバス、印刷、隊列表一覧などのUI
- `src/utils/`: 保存、座標、音源、書き出し、共有ファイルなどの処理
- `src-tauri/`: Windowsダウンロード版用のTauri設定
- `src/types.ts`: 主要な型定義
- `docs/`: 仕様メモ

主なコマンド:

- `npm run dev`
- `npm run build`
- `npm run preview`
- `npm run desktop:dev`
- `npm run desktop:build`

Windowsダウンロード版は、Web版のReact/Vite実装をTauriで包む方針です。Windows版だけの処理を追加する場合も、可能な限りWeb版のデータ構造・保存仕様・UIロジックを共通利用します。
ローカル環境にRust/CargoやMicrosoft C++ Build Toolsがない場合は、GitHub Actionsの `Build Windows Desktop App` ワークフローでWindowsインストーラーを作成できます。

## 3. 基本モード

### 3.1 ステージモード

固定されたステージ上で、シーンごとの静的な隊形を作成する通常モードです。

基本方針:

- ステージ全体が画面内に収まる表示を基本にする。
- ステージの初期表示と未訪問シーンは全体表示（100%）にし、セッション中のシーンごとの倍率・スクロール位置の記憶は維持する。
- シーンの `timeSec` に応じて静的な配置を切り替える。
- シーン間の自動補間・自動アニメーションはMVPから外す。
- メンバー・道具・幕・マーク・範囲などをシーンごとに配置する。
- 表示/非表示と道具割当はシーンごとに管理する。
- フルスクリーンでは、固定ステージを見やすく表示する。
- ステージモードのUI変更は、パレードモードへ不用意に影響させない。
- 0mの側に観客がいる。枠内の「客席側」「奥」「上手」「下手」や客席側の目印は表示しない。上・左右の目盛りと数字、縦の最前0m、位置カードの「最前から」の距離は維持する。
- 「正面方向」「0m基準位置」「ステージラベル」の設定UIは表示しない。`frontDirection`・`audienceSide`・`originMode`・`showStageLabels` の保存フィールドと値、既定値・欠落値補完は維持し、書き戻し・移行は行わない。`showStageLabels` は表示では無視する。
- 旧データの `frontDirection` は従来どおり縦目盛り・格子・吸着の原点と位置カードの距離に反映する（topは内部y=0、bottom・left・rightは実効奥行き側が0m）。旧設定の修正欄は設けない。`originMode` は表示計算に影響しない。

### 3.2 パレードモード

縦に長いルート上を前進しながら踊る、パレード形式の隊列表を作るモードです。

基本方針:

- 全体距離分の縦長キャンバスを持つ。
- 全長を無理に画面内へ縮小しない。
- 縦スクロールとズームで編集する。
- 左右にm目盛りを表示できる。
- 5m/10mごとの水平ラインを強調する。
- パレード操作ボタン群は隊列表の左側に整理する。
- 画面右側はできるだけ隊列表表示に使う。
- フルスクリーンは「全体表示」ではなく、編集領域を広げてスクロールできる状態にする。
- 隊列表上部に大きな操作バーを置かない。
- シーン小窓、パレード操作パネル、隊列表キャンバスを横並びにし、隊列表キャンバスの縦方向表示領域を広く使う。

## 4. 横方向表示

### 4.1 センターから1m刻み

センターにも立てる並び。センターから1mごとに 1, 2, 3。
横目盛りは全幅のセンターを基準に ±1, ±2, ±3m に符号・mなしの数字を表示し、センターは空欄とする。
奇数幅・小数幅でも同じセンター基準で計算する。

### 4.2 センターから0.5mずらし

センターをはさんで立つ並び。最初の1はセンターから0.5m、以後1mごと。
横目盛りは ±0.5, ±1.5m… に 1, 2, 3 を表示し、センターは空欄とする。端の包含条件は既存の仕様を維持する。

両方式をステージ・パレード、編集・印刷・画像/PDF書き出しで共通利用する。
16mを超える幅ではセンターから左右対称に番号を間引く。切り出し後も元の全幅のセンターを基準にする。
数字の位置には1mごとに縦線を引き、数字を間引いても線は残す。編集画面の「ステージ」→「詳しい設定」で横・縦の数字／5ごと／10ごとの線の濃さを個別に選べる。新項目は既定OFFで通常線として描き、パレード既存の縦5m/10mの設定・既定ONは維持する。外枠・センター線・数え方の線・細い線の順に優先し、重複する位置は1本だけ描く。
横グリッドと吸着の原点は、対象シーンの実効幅のセンター（①）またはセンター＋0.5m（②）。細線と吸着位置は原点＋整数×グリッド間隔とする。演者視点は内部座標で計算してから反転し、切り出しでは元の全幅で計算する。
横の吸着はドラッグ・新規メンバー配置・貼り付けの入口だけに適用し、既存座標、数値入力、相対移動、整列、読み込み、Undo/Redo、共同編集受信、方式切替では再吸着しない。複数選択は主メンバーを全員が収まる範囲内で吸着し、全員に同じ移動量を適用する。端は範囲内の最近傍格子点、有効点がなければ範囲制限を優先。ガイド吸着は格子より優先する。
道具は回転後の矩形の外接範囲で移動を制限する。保存座標は回転前の左上、回転は中心まわりの度のままとし、負の保存座標も許容する。外接範囲がステージより大きい軸は左／上端を0へ寄せる。道具の吸着候補は範囲内の格子点と両端とし、最近傍を選ぶ。端を越える移動は端へ吸着するため、半端な寸法でも端に接する。ガイドを優先し、最終制限で外れたガイドは表示しない。既存の吸着方式・間隔・原点、幅など長さの0基準の丸めを維持する。読み込み・回転のみ・Undo/Redo・共同編集受信・選択では位置を補正せず、次の実際の移動で制限する。
任意間隔（0.3mなど）や2mでは、②の吸着点が左右対称にならない場合がある。座標表示・数値入力・後方距離・スクロール・ズームは維持する。
縦の細線・数字線・位置吸着は同じ原点を使う。ステージは対象シーンの実効奥行きと `frontDirection ?? audienceSide ?? "bottom"` から縦目盛りの原点を決める（topは0、bottom・left・rightは奥行き）。内部座標で全シーン奥行きの線を計算してから視点反転・切り出しを行う。奥行き5.4m／0.5mでは内部y=0.4,0.9,…,4.9の10本。書き出しの0mは常に客席側（編集画面と同じ原点）とし、上下を上書きする選択欄は設けない。格子の半端はその反対側に残す。0.3mなど1mを割り切れない間隔は、数字線との近接が残り得る。
縦の位置吸着はメンバードラッグ・貼り付け、道具ドラッグ（ステージは中心／0.25m）、既存の注釈吸着に適用する。新規ステージメンバー配置へ縦吸着を追加しない。範囲内の最近傍格子点を選び、点がなければ範囲を優先する。両軸とも複数選択の共通可動範囲で主メンバーを吸着し、同じ移動量を全員へ適用して端で隊形を保つ。ガイド優先、ステージのGrid OFFの挙動、寸法の0基準の丸めを維持する。
パレードの縦格子は内部y=`totalDistance + k×間隔`。メンバーはセル間隔・範囲[0,全長＋後方距離]、道具は保存左上座標を0.25mで吸着し、回転後の外接範囲が幅・全長＋後方距離の内側に収まる範囲と両端を使う。距離変換のclamp・丸めを途中に挟まない。貼り付けはstage.showGridに依存せず、メンバーは常時セル吸着、道具は未吸着のクリック中心から左上へ変換して0.25m吸着する。パレードのコンテキストメニュー追加も貼り付けと同じ規則で入口だけ吸着する。通常の追加で使う表示領域の中央などの既定位置は従来の扱いを維持する。注釈の全長原点は維持する。全長・後方距離がセル間隔の倍数なら単独メンバーの格子・両端は従来と一致する。
以上は描画と今後の操作だけの変更で、方式切替・読み込み・ZIP・共同編集受信で既存座標を再吸着しない。複数選択の端処理とパレード道具貼り付けは意図した操作変更。
新規ステージ作成のグリッド間隔は0.5m。既存データと欠落値補完は変更せず、パレードの1マスあたりの距離の既定値は1mを維持する。
保存値はステージ meters / centerSplit、パレード normalMeter / centerSplit のまま。旧データ補完・旧別名・ZIP・共同編集スキーマも維持する。
新規作成のみ両モードの既定値は「センターから0.5mずらし」。既存データ・複製・テンプレートは元の設定を維持する。
作成画面は名前・任意音源・大きさ・横の数え方を表示し、その他は「詳しい設定（あとから変更できます）」へまとめる。
編集画面のステージタブの「詳しい設定」は、ステージ・パレードとも最初から開く。利用者は閉じられるが開閉は保存しない。音源パネル・新規作成画面の折り畳みは変更しない。
送信時は折り畳み内も検証し、不正値があれば開いて該当入力へフォーカスし、エラー説明を関連づける。

## 5. シーン

シーンは、曲中のある時刻における静的な隊列表です。

基本仕様:

- `FormationFrame.timeSec` はシーン開始時刻。
- 再生中は、現在時刻以下で最も後ろのシーンを表示する。
- 次シーン開始時刻までは現在シーンの配置を維持する。
- シーン途中でメンバーや道具を勝手に補間移動させない。
- 非表示メンバーや非表示道具を次シーンから先取りして表示しない。
- シーン一覧・番号・前後移動は常に時刻順。同時刻は保存配列の順を保ち、表示用の並べ替えでは保存配列・共同編集データを変更しない。
- シーン詳細の「時刻」は分:秒（1秒未満切り捨て）で表示し、押すと分・秒のダイヤルが開く。「決定」だけで整数秒を保存し、1回の決定は1回のUndoとする。「取消」／Escapeでは保存しない。開始時と同じ分:秒なら小数秒を含む既存値を保持し、履歴も作らない。
- ダイヤルの対象ID・開始時刻・上限は開いた時点で固定する。曲の長さが有限で正なら上限は「曲の長さ＋60秒」と開始時刻の大きい方、不明なら「60分」と開始時刻の大きい方。開いている間の音源変更・遠隔更新では草稿をリセット／切り詰めない。無変更の決定は最新の遠隔値を保持する。
- 選択変更（再生による切り替えも含む）・対象削除・タブ移動・編集権限喪失は取消。決定時も対象と権限を確認する。ダイヤル中はシーン一覧の自動スクロールを抑止し、閉じた後は詳細表示へ追従する。手動ドラッグ並べ替え・時刻順ボタンは表示しない。
- 時刻ダイヤルはくり返し設定と共通。最終分の秒は上限の小数秒を切り捨てた範囲まで。分の描画行数は制限する。上下／Home／End・名前付き＋−を使え、閉じると起動元へフォーカスを戻す。native dialog非対応環境も背景操作とTab移動を遮断する。くり返しの「開始＜終了」検証と小数秒を含む「曲の終わり」は維持する。

シーン小窓:

- シーン小窓は固定サイズにする。
- シーン数が少なくても縦に引き伸ばさない。
- シーン数が多い場合は小窓リストだけスクロールする。
- 小窓内の表示は簡潔にし、シーン番号は数字中心にする。

## 6. メンバー

メンバーはステージまたはパレード上に配置できる隊列表の基本要素です。

主な仕様:

- メンバー名は円内に表示する。
- 文字数は見た目の1文字（Intl.Segmenterのgrapheme、未対応環境はArray.from）で数える。1文字は中央、2・3文字は横1行、4文字は2×2とし、1〜4文字の分割・サイズ・CSSを維持する（AB12・Yukiも同じ）。5文字は上3・下2、6文字は3×2とし、長い名前だけ縮小する。
- 7文字以上で印字可能な半角ASCIIだけの名前は12文字まで省略せず、ceil(n/2)で2行に分ける（Takahashiも全表示）。13文字以上は先頭10文字＋「…」を2行。それ以外の7文字以上は先頭5文字＋「…」を3×2（あいう／えお…）。空白の位置では改行しない。表示内容はズームで変えず、保存名・title・アクセシブル名、選択カード・名簿は全名を保持する。
- 5文字以上のサイズは、全角約1em・半角約0.6em・幅広英字は保守的な幅見積もりと、実直径・枠・行高・字形の高さから円の弦に収まる最大サイズを計算する。上限は直径×0.3、画面の下限は8px。直径31pxで全角5・6文字と省略名が8px以上で円外にはみ出さず収まることを基準とし、白い枠への約1pxの重なりは許容する。丸がさらに小さい極端な縮小では可読下限を優先し、同じ表示内容を保持して縁への重なりを許容する（行内clipはしない）。
- 印刷・画像/PDFは既存の下限1.8mmと0.2mmの補正を維持し、5文字以上は補正加算後の最終サイズに収まり制限を適用し切り捨て丸めする（下限へ補正を再加算しない）。短い名前の印刷サイズは維持する。幅広英字が12文字続く名前や極端に小さい印刷の丸など、全表示・可読下限・円内の収まりが物理的に両立しない場合は、全表示と可読下限を優先する。
- メンバー色は個別色、グループ色、シーンごとの色上書きを扱う。
- シーンごとの色上書きは `memberAppearanceOverrides` で管理する。
- メンバー同士が完全に重なりすぎて見失わないようにする。
- 新規追加したメンバーは追加したシーンでは表示、その他のシーンでは自動で非表示にする。

### 名簿のPDF書き出し（2026-10-21）

- 名簿PDFはExcelと同じ「No.＋グループ別のメンバー名」の表1種類。演目名・日付・人数・道具・ページ番号は付けない。Excelと列選択・色の正規化を共通利用し、空の登録グループを残す。未所属は人がいる場合のみ最後に出し、完全空なら「No.」「未所属」の見出しのみ。PNGの列選択は変更しない。
- 見出しとNo.列はF1F5F9背景・太字・中央、名前はRegular・中央。見出しは色付き「■ 」と黒0F172Aの名前を別runにし、下線はグループ色の太線。縦罫線0F172A、横罫線D5DBE3。名前のあるセルだけ罫線を引き、短い列の下は白紙にする。
- 名前は11pt。Intl.Segmenterのgraphemeで6文字以下は1行、7文字以上はまず2分割（奇数は前半が1文字多い）。両側が空にならない空白のうち中央に最も近い位置を優先し、同距離なら前半が長い方。区切りの空白は行端に残さない。その後、列幅に入らない行だけ追加で折り返し、省略しない。列幅は名前の実測で通常30〜50mm・左右余白2mm。6文字の全角名は11ptで約23.3mmなので最小幅内に収まる。幅広い6グラフェム以下の名前は1行を守るため50mmを超えて広げ、片方のA4の向きだけに入る場合はその向きを使う。両方の用紙幅にも入らない場合は説明して中止する。
- 長い見出しは列幅を広げず折り返す。同じ横分割の見出し高と各行高はセルの最大に揃える。A4縦・横でページ数を比較し、少ない方、同数は縦。横に入らない列を連続する列単位で分け、各横分割の縦ページを先に出す。見出し・No.は毎ページ繰り返し、No.は縦の続きで継続し横分割で1に戻る。行の途中で分割しない。1行が見出しを含めてA4の高さを超えたら理由を表示して中止する。
- PDF選択時は用途・1枚／複数枚・スマホ配置の事前判定を表示・実行しない。画像の用途・配置・分割・事前判定とExcelのセル・装飾は維持する。
- 専用の表DOMを48件ずつ計測し、同名・幅・書式の結果は出力処理内だけ再利用する。名前はtextContentで配置。1ページずつDOMを生成・計測・破棄し、全ページのDOMは保持しない。固定の用紙内寸で画像版と同じ端数処理・最終倍率を用い、表の外接寸法へ拡大しない。
- BIZ UDPゴシックRegular／Bold、文字分類、グラフェム画像代替、サブセットと元TTFでの再作成、取消は共通rendererを利用する。fillStrokesはOFF、罫線は境界ごとに1回。画像代替文字はPDFの文字抽出には含まれない。文脈依存文字など文字分類上安全に描けない場合だけ、新しい表DOMから文書全体を画像PDFにする。先頭プレビューも同じ表DOM。旧スマホPDF・旧A4名簿PDFは削除する。
- 名簿PDFは合計20万UTF-16単位・1万人・256グループ列・100ページまで。画像は先頭プレビュー／全体画像代替合計4,000万画素、グラフェム画像は共通上限（400万画素・256種類）。上限超過・計測／描画／フォント異常では重い画像方式へ戻さず作成を中止。Intl.Segmenterが無い環境は理由を表示して中止する。保存スキーマは変更しない。iPad Safari／WKWebView・LINEのプレビューは実機未確認。

### 名簿のExcel書き出し

- 全体名簿のメンバー管理にある「書き出し ▾」→「Excel（.xlsx）」から作成する。Excelでは用途（A4／スマホ）・画像配置の判定やプレビューを表示しない。
- 道具がある場合だけ「道具も含める」を表示し、既定オン。オフまたは道具なしではメンバー1シートのみ。オンでは道具を加えた2シート。
- 「メンバー」「道具」ともA1は「No.」、B列以降はアプリと同じグループ別の列で、名前だけを出す。グループ順・グループ内順・重複所属の先着優先・欠落IDの無視はcollectGroupedItemsを再利用する。空の登録済みグループも残す。アプリと異なり、未所属列は未所属の項目があるときだけ最後に出す。登録グループも項目もない完全空の名簿は「No.」「未所属」の見出しだけ。
- 2行目以降のNo.は最長列の人数まで1,2,3…（アプリと同じ行番号）。短い列の下には空セルを書かず、追加行も出さない。道具の種類・形・寸法・内部ID・座標・担当・表示状態は含めない。
- B案「見出しは線だけ」: 見出し背景F1F5F9・太字・文字0F172A・中央揃え。グループ色の「■ 」をリッチテキストで先頭に付け、下罫線はグループ色のthick。縦の罫線（列の区切り）は見出し・名前・No.とも0F172Aのthin（利用者決定 2026-10-14: 片側だけのグループ色の線は隣の列の線に見えるため）。横の罫線は灰色D5DBE3のthin。名前セルは中央揃え。No.列は背景F1F5F9・太字・中央揃え。グループ色は見出しの「■ 」と下罫線だけで示す。
- 個別色ではなくグループ色を使用し、未所属は94A3B8。DOM非依存で#RGB/#RGBA/#RRGGBB/#RRGGBBAA・rgb()/rgba()を解釈し、透明度を白背景に合成してFFRRGGBBにする。空・不正・名前色など未対応色はFF94A3B8。見出しスタイルは両シート共通で正規化色ごとに1つ、名前セルは全列で1つのスタイルを共有する。
- 目盛線は非表示、見出し行26・通常行22、No.列幅7・名前列幅15以上50まで（全角2.2・半角1.2＋余白3で見積もり）。行の高さが固定なので折り返さない。先頭ゼロの名前などに「数値が文字列」の警告印を出さない（ignoredErrors numberStoredAsText）。見出し行とA列を固定（xSplit=1,ySplit=1,topLeftCell=B2）。印刷の「幅に合わせる」は設定しない。
- 列名はA..Z,AA..XFD。No.を含め16,384列、見出しを含め1,048,576行を超える場合は説明して作成を中止し、切り捨て・シート分割はしない。
- 名前・グループ名はinlineStrの文字列セル（先頭ゼロ・数式風の名前も保持、アポストロフィを付加しない）。XML特殊文字・制御文字・OOXMLの特殊文字表現をエスケープし、「■ 」も含め32,767 UTF-16単位を超えるセルは作成を止めて説明する。No.は数値セル。
- 形式メニューは書き出しボタン直下の右端揃えで絶対配置し、下のタブ・人数欄を動かさない。カードメニューと同じ外観で「画像・PDF」「Excel（.xlsx）」を表示し、外側タップ・Escape・項目選択で閉じる。role=menu/menuitem、aria-expanded、矢印・Home/End・Enter/Space・Tabに対応。従来どおりメンバー管理でのみ表示し、道具管理には書き出しボタンを追加しない。
- IME入力中は確定を案内する。作成前にblurと残る名簿の下書きを確定し、最新データのスナップショットを取る。ファイル作成と共有・保存を分離し、取消・失敗後は作成済みファイルを再利用する。
- ファイル名は「演目名_名簿_日時.xlsx」。既存のファイル名処理を再利用し、演目名を最大60コードポイントに制限する。MIMEはapplication/vnd.openxmlformats-officedocument.spreadsheetml.sheet。
- iOSは既存の共有シート、Webは保存・ダウンロード経路を使う。既存JSZipを遅延読込し、新規依存・保存スキーマ変更・Excelからの取り込みは追加しない。

## 7. 道具

### 新規作成時の名簿コピー

- 新規作成の「名簿をコピー（任意）」は詳しい設定の外に置き、両モードで表示する。既定は「コピーしない」。隊列表カードの「…」→「この名簿で新しく作る」も同じ作成画面を開き、コピー元とそのモードを選択済みにする。作成タイプは変更できる。
- コピー元はRepositoryに端末保存された内容だけ。名前・更新日・人数で区別し、クラウド本文を直接取得しない。読み込み失敗では作成せず、入力を保持してエラーを表示する。
- メンバーの名前・個別色・配列順、グループの名前・色・グループ内順をコピーする。「道具もコピーする」は既定オン、道具なしでは無効。道具の名前・色・種類・保存された形（旧形状も保持）・objectBaseSizeで求める普段の寸法、道具グループと既定種類／形をコピーする。
- Project・メンバー・道具・グループ・初期シーンは新ID。参照を対応表で置換し、一括で新Projectを生成する。保存スキーマは変更しない。
- コピー先のモード・寸法・表示設定を優先する。位置はコピー先の既定配置。全体表示はtrue、最初のシーンは全員・全道具が非表示。「すべて表示」で表示できる。回転・ロック・重なり順は初期化する。
- コピー元のシーン・位置・シーン別色・道具割当・音源・注釈・メモ・カメラ・共有／同期／共同編集情報は引き継がない。
- 道具の普段の寸法がコピー先の幅／奥行き（パレードは幅／全長）を超える場合、「ステージに入らない道具があります」で道具名・寸法とコピー先寸法を表示する。「ステージに入る大きさに縮めてコピー」ははみ出す軸だけ合わせ、「入らない道具はコピーしない」は入る道具のみ、「戻ってステージの大きさを変える」は入力を保持して作成画面へ戻る。黙って縮小・除外しない。
- 保存は既存Repository経路。保存失敗では新Projectを未保存のまま保持し、既存の再試行を使う。保存に失敗したときは成功通知を出さない（成功時は通常の新規作成と同じ「新しい隊列表を作成しました。」）。

道具は、幕、椅子、机、パネル、マーク、範囲、カスタムなどを含む配置要素です。

主な仕様:

- UI上は「道具」に統一し、幕も道具の種類として扱う。
- 道具グループを持つ。
- グループ所属道具はグループカード内だけに表示し、未所属一覧には重複表示しない。
- 表示切替リストは例外として全道具を表示してよい。
- 新規追加した道具は追加したシーンでは表示、その他のシーンでは自動で非表示にする。
- 道具のマウス移動はグリッド設定に従い、現在重視する移動単位は0.25m。
- 名簿の「道具管理 → 名前の編集」で、道具のアイコンまたは名前を押して形・大きさを設定する。追加した道具は返された新IDで選択する。広い画面では上部帯の右側、利用可能幅が狭い画面では表の上に編集欄を置き、折り畳める。メンバー管理・道具割当は既存の画面を維持する。
- 形の選択UIは押し直せる「□ 四角形」「⬭ 円」の2ボタン。保存・読み込み・共同編集では既存5値を維持し、旧curtain/custom/lineは変更せず描画する。選択UIだけ四角形として表示する。新規幕プリセットはtype: curtain・shape: rectangleとし、既存の縞を描画時に維持する。
- 普段の寸法は、その道具の保存済みobjectStatesの幅・高さの組の最頻値。同数または保存状態なしなら登録寸法。道具1個の寸法確定で登録寸法を更新し、この基準と誤差1e-6以内で一致する保存状態だけ中心を保って更新する。はみ出す場合だけ内側へ補正し、実効シーン寸法に収まらない場合は理由を表示して拒否する。個別に異なる状態、欠落状態、回転・表示・割当・zIndexを保持する。ステージ上の寸法編集はそのシーンだけ。
- 名簿の寸法は最小0.1m・小数2桁まで。ドラッグは0.1m刻み、開始時の倍率を固定して終了時に確定する。数値入力は確定／取消、±ボタンは0.10mを1回ずつ加減する。1確定は1更新・Undo1回、無変更では履歴を作らない。確定は最新Project・対象・編集可否で再検証し、変更した軸だけ最新値へ適用する。草稿は選択変更・タブ移動・削除・権限喪失・画面回転・pointercancelで破棄する。
- グループ内の新規追加は、所属道具の保存shapeと普段の幅・高さの組で1道具1票の最多組を引き継ぐ。欠損IDを除外、重複IDは1票、同数はobjectIds順。空ならdefaultShapeと通常の既定寸法。コピー・貼り付けは元の寸法を保持する。
- 所属変更は形・寸法を保持する。移動先と道具の色が異なる場合だけ「はい／いいえ」で色も合わせるか確認し、閉じると「いいえ」として所属だけ変更する。確認後に対象・移動先・色・編集可否を再検証し、色が変わっていれば再確認する。未所属への移動は色を保持し、グループ色変更への自動追従は行わない。
- 共同編集の道具確定は1トランザクション。複製Docで同じrecipeのYjs更新サイズを事前計測し、256KiBを超える場合は実Doc・履歴・outboxを変更せず拒否する。geometryの既存一括同期を維持するため、未受信の同時移動との競合や、遠隔編集後のUndoのpartial／blockedは既存の通知経路で扱う。

## 8. 道具割当

道具割当はシーンごとに管理します。

基本仕様:

- `FormationFrame.objectAssignments?: Record<objectId, memberId[]>`
- 道具別ビューとメンバー別ビューを持つ。
- 道具別ビューでは、そのシーンで表示中の道具だけを対象にする。
- 非表示道具は、そのシーンで使わないため割当対象に出さない。
- 割当メンバーは、そのシーンでは隊列外として扱う。
- メンバータブ非表示側には `割当: 道具名` を表示する。
- メンバー別ビューでは「道具」と「非表示」だけを表示し、「踊り」「出番」は表示しない。
- 道具表示順はグループごとにまとまるようにする。
- 直前シーンで同じ道具が表示中の場合、ワンクリックで割当を引き継げるようにする。

## 9. 選択対象の座標カード

- 詳細タブは設けず、メンバー・道具タブの通常見出し・操作の下、このシーンの表示の上に座標カードを表示する。縦画面でも上部に置く。
- 単独選択のメンバーは名前と色、横・縦位置を表示する。複数選択では人数だけ表示する。
- 道具は名前と横・縦・幅・高さ・回転を表示し、寸法・回転の編集欄はこのカードに集約する。最小寸法0.01mと、寸法変更時の位置補正を維持する。
- 既存の座標変換、センター割りの左右表示、実効シーン寸法、パレードの後方距離を維持する。数値入力に吸着を適用しない。
- 再生中・閲覧のみでは入力を無効にする。変更は既存Undo経路で保存する。
- Ctrl/Cmd+1は選択対象のタブを開いてカードへフォーカスする。未選択ならメンバータブを開く。
- 座標の見方・ショートカットは使い方に掲載する。previewモードと保存済みanimationSettingsは維持する。

## 10. 保存と共有ファイル

保存:

- collaborationV2有効時、ホーム「…」→「クラウドに保存」と編集画面「共有を始める」は共通処理を使う。恒久アカウント・対象ID・操作世代を確認し、未ログイン・ゲストにはログイン案内だけを出す。コピーは作らず、ログイン後の自動再開もしない。既知のオフラインと旧本人クラウドsyncはコピー前に拒否し、旧syncではホームの複製へ案内する。
- 押した時点の未保存編集を端末に保存し、同名の独立したコピーを保存した後、元IDのまま共有を始める。コピーは新ID・新作成/更新日時・localRevision "1"・共有/syncなし。音源IDと内部メンバー/シーンIDを保持し、音源本体は複製しない。lastOpenedAtは通常の複製と同様に作成時刻。コピーは開かず、以後の共同編集を受け取らない。成功後は元の編集画面にとどまり、ホーム入口では元の隊列表を開く。招待発行は行わない。
- コピー保存失敗では共有通信を行わず、画面状態とUndoを保持する。共有開始失敗でも保存済みコピーは残し、クラウドへの保存が未確認である旨を通知する。共通busyで二重押しを防止し、同一アカウント・元ID・内容の再試行では固定コピーID/operationId/内容を再利用する。編集後は新しいコピーを作る。再起動をまたぐ重複防止は今回の対象外。
- 通信待ち中は世代・アカウント・元レコードのrepositoryRevisionを確認する。編集中の新しい内容は画面に保持し、返信後に開始時点から変更した項目だけを元IDの共有セッションへ適用し、別経路の更新を丸ごと上書きしない。コピー/事前検証の失敗では開き直さない。共有開始成功時は既存仕様どおりUndo履歴をリセットする。
- カードの印は「クラウド」（参加者1人、または未ログイン・オフライン・未読込・読み込み中で人数不明）／「共有中・N人」（2人以上）。端末カードとクラウドのみのカードは共通の表示関数を使う。人数は軽量一覧ui.documentsのaccountIdとdocumentIdを照合してメモリ内で利用し、保存スキーマや認可判断には使わない。ホーム表示・手動更新・参加者変更後に一覧を更新する。一覧更新失敗は共有開始失敗に含めない。
- 端末カード上段は印と44×44px以上の「…」、下段はプレビュー・名前の開く領域。間に8pxの非操作余白を設け、プレビューへボタン/透明な当たり判定を重ねない。iPad mini幅744pxでは3列を維持する。メニュー項目も44px以上とし、実測で画面内に配置し、必要時はメニュー内をスクロールする。
- 隊列表データはWeb/WindowsではIndexedDB、iPadアプリではネイティブSQLite Repositoryへ1件単位で保存する。
- 起動時に旧データを移行し、旧localStorage・iPadミラーは読み取り専用で残す。本人クラウドの下書きファイルは別経路を維持する。
- 音源ファイル本体は端末のみへ保存する。Web/WindowsはIndexedDBのBlob、iPadネイティブはApplication Support内のファイルを使い、IDから解決したURLで再生する。旧iPad音源はコピー移行し、元ファイルを残す。
- 隊列表データ側には音源メタ情報を保存する。
- 復元候補・検証済み端末バックアップからの復旧、手動全件バックアップ、音源GC、利用者による旧データ整理を提供する。安全条件と未確認項目は `docs/STORAGE_RECOVERY_BACKUP.md` を参照する。

共有ファイル:

- サーバー不要のファイル共有を基本にする。
- ZIP形式で書き出し・読み込みする。
- `.tairetsu` と `.zip` の読み込みをサポートする。
- LINEやiPad経由でMIME typeや拡張子が変わっても、最終的にはZIP内部の `manifest.json` と `project.json` で判定する。
- ZIP内部ファイル名はASCII固定名にする。
- 共有リンク機能は使わない方針。
- JSON単体バックアップは優先度低め。

読み込み判定:

- 拡張子やMIME typeだけで拒否しない。
- `.tairetsu`、`.zip`、`application/octet-stream`、MIME type不明のファイルでも、ZIPとして展開できれば検証する。
- 最終判定は `manifest.json` と `project.json` の存在、`fileType`、`formatVersion` で行う。
- 不正ファイルではアプリを落とさず、分かりやすいエラーを出す。

## 11. 印刷

印刷機能は、アプリ画面全体ではなく隊列表そのものを出力することを目的にします。

現在重視する仕様:

- 各シーンのステージ画像とシーン名だけを出力する。
- 時間情報、メモ欄、操作UI、デバッグ表示は出さない。
- 全シーンを縦に並べる。
- 適切な余白を入れ、グリッドの連続感を保つ。
- 印刷/PDF保存しやすいレイアウトにする。
- 既存の編集画面UIは印刷に含めない。
- 印刷対象はステージグリッド、メートル目盛り、センターライン、メンバー、道具、幕、ステージ枠線を基本にする。
- 選択枠、リサイズハンドル、右クリックメニュー、ツールバーは含めない。
- 全シーンを縦に並べる場合、ページ分割が自然になるようにする。

閲覧用の書き出し:

- ステージのA4 PDF・画像とカメラ保存のPNG・PDFは「書き出す向き」で「踊る人側から見た向き／観客側から見た向き」を選べる。初期値はAppの現在の編集視点とし、選択はダイアログ内だけで保持する。隊列表に保存せず、編集画面の視点も変更しない。パレードは従来の向きを維持し、向きの選択欄は表示しない。
- 点・道具矩形・注釈線・目盛り・格子はシーンごとの実効寸法を使い、内部座標で計算してから視点を反映する。メンバー名・目盛りなどの文字は正立。ステージ図の道具の回転は維持し、道具名は道具の向きに沿わせるが、逆さに読める角度（90°を超える回転）では180°補正して文字の角度を(-90°, 90°]に収める（細い斜めの道具でも名前が枠内に収まるように）。右側の割当欄の道具は回転0で描く。
- 名簿割当の大プレビューとシーン帯は現在の編集視点に追従する。メンバー名簿の文字表の出力はこの視点選択の対象外。
- 隊列表はA4だけとし、「このシーン／全シーン」と形式「PDF／画像」を選べる。道具割当欄の有無を両形式で選べる。
- A4 PDFの既存ページ分割・描画・用紙・20ptの余白・中央への収まり方を維持する。
- ステージのA4 PDFはベクター描画を既定とし、BIZ UDPゴシックを必要なウェイトだけ読み込み、使用文字のサブセットをPDFへ埋め込む。現行A4はBoldのみ。TTFのバイト列はセッション内で再利用するが、各PDFの解析・使用文字情報は共有しない。
- 改ページ・共通倍率・レイアウト定数は画像版とベクター版で共通利用する。道具割当欄の列・折り返しは既存CSSの配置を計測し、道具と担当メンバー・文字をベクターで描く。割当メンバーのぼかし影だけ小さい透過画像を共有する。
- 道具はrectangle・circle・curtain・line・customに対応する。幕は既存の塗り・枠の内側へ、左から白28%の8px幅／16px周期の縞をクリップして重ねる（1px＝25.4/96mm、最終A4配置倍率を適用）。ステージでは道具と一緒に回転し、割当欄は回転0。線・カスタムは従来の印刷CSSと同じ四角として描く。保存された形・座標は変更しない。未知の形は文書全体を画像PDFへ戻す。
- 共通フォントで安全に描ける通常文字は連続runでベクター描画する。独立描画できる欠字・絵文字・補助漢字・結合列（ZWJ・肌色修飾・VS16・IVS・結合文字）はグラフェム単位の小さい透過PNGで代替し、同じ文字・書式・解像度の画像を文書内で再利用する。対象はステージのメンバー名・道具名・割当欄の名前・シーン名。配置と基準線は同じBIZ＋端末フォントの未回転DOMから取得し、既存の回転・クリップを適用する。フォントのサブセット・Unicode検証はベクターrunだけを対象とし、PDFメタデータの題名とは分ける。
- ハングルの完成形音節（U+AC00〜D7A3）と互換字母（U+3130〜318F）は独立した字形として画像代替できる。結合用字母（U+1100〜11FF、U+A960〜A97F、U+D7B0〜D7FF）を含む列は合成が必要なため、文書全体を画像PDFへ戻す。
- アラビア文字など文脈依存文字、制御文字、必要なIntl.Segmenterの欠落、代替PNGの作成失敗・空画像・既知の豆腐との一致・資源上限超過、未対応の道具形状・オプション、フォント読込／解析や生成の異常時は、文書全体を従来の画像PDFへ自動で戻す。代替PNGは最終紙面384dpi相当、辺1024px・文書合計400万画素・256種類を上限とする。端末の欠字を完全に判定するAPIはないため豆腐検出は最善努力。理由はセッション内の診断情報に記録し、通常の画面には表示しない。パレードは当面、従来の画像PDFを使用する。iPadのWKWebView・SafariでのApple Color Emojiの画像化は実機確認が必要。
- A4 PDF生成中は進捗と「取消」を表示する。取消では画像方式へ戻さず終了し、完成画面を出さない。既存のゲージのtransformアニメーション、先頭ページのプレビュー、完成画面のファイルサイズ・共有／保存の操作は維持する。PNG・カメラ保存は従来経路を維持する。メンバー名簿PDFは§6の専用表DOMから共通rendererへ渡し、隊列表のページ構成・シーン分割・倍率・paradeA4Limitsは使わない。
- A4画像は各 `.print-page` を1枚ずつ2倍で描画し、PDFと同じ用紙・余白・収まり方の白いA4へ約192dpiで配置する。Canvas→Blobをページ順に逐次処理し、各Canvasを解放する。全ページを縦長Canvasにしない。
- 画像名は `演目_隊列表_日時_001.png`。ページ連番は最低3桁で、総数の桁数に合わせる。複数枚には画像内にも `1/12` のようなページ番号を付ける。1枚の場合は画像内番号を省く。
- 共有シートへ渡す画像配列とWeb完了画面の個別保存ボタンはページ順を維持する。写真アプリ保存後の並びは保証範囲外。
- メンバー名簿PDFはExcelと同じメンバー表の1種類に統一する。画像はスマホ向け・A4を維持する。道具名簿と道具割当表（スマホ用）の画像／PDF書き出しは廃止する。Excel名簿には任意で道具シートを含められる。登録・管理・割当編集・保存データ・A4隊列表の割当欄は維持する。
- スマホ向け隊列表の専用出力経路は削除する。名簿割当画面やサムネイル等が使う静的描画・範囲計算は維持する。
- ZIP・バックアップは再編集用であり、PDF／画像選択の対象外。

## 12. スクリーンショット

ステージ周辺だけを画像またはPDFにする機能です。ステージのカメラとパレード左側の画像保存で形式を選べます。PDFは既存画像の余白・縦横比を維持し、追加余白のない1ページに配置します。

含めるもの:

- ステージグリッド
- 上メモリ数字
- 左メモリ数字
- メンバー
- 道具
- 幕
- センターライン
- ステージ枠線

含めないもの:

- 左パネル
- シーン一覧
- 再生バー
- 上部操作ボタン
- カメラボタン自身
- 選択枠
- リサイズハンドル
- ホバーUI

PCでは保存とクリップボードコピー、iPadでは共有シートやプレビューなど、Webブラウザの制約内で最も使いやすい方法へフォールバックします。

実装方針:

- 画面全体ではなく、ステージ表示に必要な範囲だけを対象にする。
- メートル数字が切れないよう、上・左・右・下に適度な余白を含める。
- 選択枠、リサイズハンドル、ホバーUI、操作ボタンは一時的に非表示にする。
- 高解像度でもぼやけにくいようにする。

## 13. UI方針

- 編集キャンバス（目盛り込み）ではネイティブの文字選択・長押しの吹き出しを出さず、アプリの長押しメニューは維持する。キャンバス外の入力欄・パネル・名簿・ヘルプは対象外。
- ステージ／パレードの長押しメニューでは、アプリ内clipboardが空で「貼り付け」が無効のときだけ、直下に「メンバーや道具を長押し→「コピー」すると使えます」と案内する。

- 白背景、薄いグレー境界線、緑系アクセントを基本にする。
- 操作ボタンは分かりやすく整理する。
- ステージやパレードキャンバスの表示領域を優先する。
- 画面上部に操作を詰め込みすぎない。
- パレードモードでは操作パネルを隊列表左側へ置き、右側を隊列表表示に使う。
- iPad横向きでも操作パネルが上部に戻りすぎないようにする。
- 横画面のメンバー・道具タブは、通常の見出し・操作、選択対象の座標カード、このシーンの表示、固定する表示／非表示切替と追加先、管理一覧の順に置く。縦画面の管理対象切替はグループ一覧の見出しに維持する。
- パレードの画像保存・拡大縮小ロック・全画面は操作パネル上部へまとめる。「スタートへ」「ゴールへ」「100%」ボタンは表示せず、ピンチ／ホイールによる拡大縮小は維持する。
- パレードの前シーン反映は「全員」またはグループを1つの対象選択で指定し、移動量0の反映と反映して移動の両方で使う。指定グループの削除時は全員へ戻す。
- パレード操作の見出し付近に、表示中かつ道具に割り当てられていないメンバーの有限な中心Yの最小値から求めた「最前 ○○m」を表示する。対象がなければ「最前 —」。画像保存には含めない。
- UI文言は日本語で統一する。
- ボタンが多い場合は、表示領域を削らない場所へ移動する。
- 文字がなくても意味が通る操作はアイコン中心にしてよいが、アクセシビリティ用の `title` と `aria-label` は残す。
- ステージモードとパレードモードで同じUIに見えても、目的が違う場合は挙動を分ける。

## 14. 変更時の確認方針

実装後は、変更内容に応じて以下を確認します。

共通:

- `npm run build` が成功する。
- `git status --short` で意図しない差分がない。
- 既存の保存データを読み込んでもエラーにならない。

ステージモード:

- 新規作成できる。
- メンバー・道具を配置、移動、表示/非表示できる。
- センターから1m刻みとセンターから0.5mずらしが既存仕様どおりに見える。
- フルスクリーンが既存どおり動く。

パレードモード:

- 縦長キャンバスをスクロールできる。
- ピンチ／ホイールによるズーム、拡大縮小ロック、フルスクリーンが役割どおり動く。
- 左右のm目盛り、5m/10mラインがずれない。
- 操作ボタン群が隊列表左側にまとまっている。
- センターから1m刻みとセンターから0.5mずらしがステージモード仕様に揃っている。

印刷・スクリーンショット・ZIP:

- 印刷にはシーン名とステージ画像だけが出る。
- スクリーンショットにはステージ周辺だけが写る。
- `.zip` / `.tairetsu` を読み込める。
- 音源あり/なしの共有ファイルで破綻しない。

## 15. 今後の実装方針

優先すること:

- 既存のステージモードを壊さず安定させる。
- パレードモードを縦長隊列に適したUIへ整える。
- スクリーンショット・印刷の品質を上げる。
- ZIP読み込み・書き出しの安定性を上げる。
- 座標カードでの編集体験を整える。

優先度が低いもの:

- 共有リンク機能
- JSON単体バックアップ
- シーン間の自動アニメーション
- 複雑な共同編集

実装時は、変更範囲を小さく保ち、ステージモードとパレードモードの分岐を明確にしてください。

大規模変更では、型定義、保存互換性、UI、印刷/スクリーンショット、ビルド確認の順に段階的に進めます。
