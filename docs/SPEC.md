# 隊列メーカー 仕様メモ

この文書は、隊列表作成アプリ「隊列メーカー」の現在仕様と今後の実装方針をまとめるものです。
Codex は実装前に `AGENTS.md` とあわせて参照してください。

## 1. アプリ概要

隊列メーカーは、ダンス、舞台、パレードなどで使う隊列表を作成・編集・保存・印刷・書き出しできるWebアプリです。

主な用途:

- ダンスステージのシーンごとの隊列表作成
- 舞台演出でのメンバー・道具・幕の配置管理
- パレード形式の縦長隊列作成
- メンバーや道具の表示・非表示管理
- 道具割当の管理
- 印刷、PDF保存、スクリーンショット、ZIP共有

## 2. 技術構成

- React
- TypeScript
- Vite
- Tauri（Windowsダウンロード版）
- npm

主なディレクトリ:

- `src/App.tsx`: アプリ全体の状態管理・画面構成の中心
- `src/components/`: パネル、キャンバス、印刷、隊列表一覧などのUI
- `src/utils/`: 保存、座標、音源、書き出し、共有ファイルなどの処理
- `src-tauri/`: Windowsダウンロード版用のTauri設定
- `src/types.ts`: 主要な型定義
- `docs/`: 仕様メモ

主なコマンド:

- `npm run dev`
- `npm run build`
- `npm run preview`
- `npm run desktop:dev`
- `npm run desktop:build`

Windowsダウンロード版は、Web版のReact/Vite実装をTauriで包む方針です。Windows版だけの処理を追加する場合も、可能な限りWeb版のデータ構造・保存仕様・UIロジックを共通利用します。
ローカル環境にRust/CargoやMicrosoft C++ Build Toolsがない場合は、GitHub Actionsの `Build Windows Desktop App` ワークフローでWindowsインストーラーを作成できます。

## 3. 基本モード

### 3.1 ステージモード

固定されたステージ上で、シーンごとの静的な隊形を作成する通常モードです。

基本方針:

- ステージ全体が画面内に収まる表示を基本にする。
- シーンの `timeSec` に応じて静的な配置を切り替える。
- シーン間の自動補間・自動アニメーションはMVPから外す。
- メンバー・道具・幕・マーク・範囲などをシーンごとに配置する。
- 表示/非表示と道具割当はシーンごとに管理する。
- フルスクリーンでは、固定ステージを見やすく表示する。
- ステージモードのUI変更は、パレードモードへ不用意に影響させない。

### 3.2 パレードモード

縦に長いルート上を前進しながら踊る、パレード形式の隊列表を作るモードです。

基本方針:

- 全体距離分の縦長キャンバスを持つ。
- 全長を無理に画面内へ縮小しない。
- 縦スクロールとズームで編集する。
- 左右にm目盛りを表示できる。
- 5m/10mごとの水平ラインを強調する。
- パレード操作ボタン群は隊列表の左側に整理する。
- 画面右側はできるだけ隊列表表示に使う。
- フルスクリーンは「全体表示」ではなく、編集領域を広げてスクロールできる状態にする。
- 隊列表上部に大きな操作バーを置かない。
- シーン小窓、パレード操作パネル、隊列表キャンバスを横並びにし、隊列表キャンバスの縦方向表示領域を広く使う。

## 4. 横方向表示

### 4.1 センターから1m刻み

センターにも立てる並び。センターから1mごとに 1, 2, 3。
横目盛りは全幅のセンターを基準に ±1, ±2, ±3m に符号・mなしの数字を表示し、センターは空欄とする。
奇数幅・小数幅でも同じセンター基準で計算する。

### 4.2 センターから0.5mずらし

センターをはさんで立つ並び。最初の1はセンターから0.5m、以後1mごと。
横目盛りは ±0.5, ±1.5m… に 1, 2, 3 を表示し、センターは空欄とする。端の包含条件は既存の仕様を維持する。

両方式をステージ・パレード、編集・印刷・画像/PDF書き出しで共通利用する。
16mを超える幅ではセンターから左右対称に番号を間引く。切り出し後も元の全幅のセンターを基準にする。
数字の位置には1mごとに縦線を引き、数字を間引いても線は残す。編集画面の「ステージ」→「詳しい設定」で横・縦の数字／5ごと／10ごとの線の濃さを個別に選べる。新項目は既定OFFで通常線として描き、パレード既存の縦5m/10mの設定・既定ONは維持する。外枠・センター線・数え方の線・細い線の順に優先し、重複する位置は1本だけ描く。
横グリッドと吸着の原点は、対象シーンの実効幅のセンター（①）またはセンター＋0.5m（②）。細線と吸着位置は原点＋整数×グリッド間隔とする。演者視点は内部座標で計算してから反転し、切り出しでは元の全幅で計算する。
横の吸着はドラッグ・新規メンバー配置・貼り付けの入口だけに適用し、既存座標、数値入力、相対移動、整列、読み込み、Undo/Redo、共同編集受信、方式切替では再吸着しない。複数選択は主メンバーを全員が収まる範囲内で吸着し、全員に同じ移動量を適用する。端は範囲内の最近傍格子点、有効点がなければ範囲制限を優先。ガイド吸着は格子より優先する。
道具は既存の吸着方式・間隔を保ち、横の原点だけ変更する。幅など長さの丸めは0基準を維持する。
任意間隔（0.3mなど）や2mでは、②の吸着点が左右対称にならない場合がある。縦目盛り・縦グリッド・縦吸着・5m/10m線・後方距離・スクロール・ズーム、座標表示・数値入力は変更しない。
新規ステージ作成のグリッド間隔は0.5m。既存データと欠落値補完は変更せず、パレードの1マスあたりの距離の既定値は1mを維持する。
保存値はステージ meters / centerSplit、パレード normalMeter / centerSplit のまま。旧データ補完・旧別名・ZIP・共同編集スキーマも維持する。
新規作成のみ両モードの既定値は「センターから0.5mずらし」。既存データ・複製・テンプレートは元の設定を維持する。
作成画面は名前・任意音源・大きさ・横の数え方を表示し、その他は「詳しい設定（あとから変更できます）」へまとめる。
送信時は折り畳み内も検証し、不正値があれば開いて該当入力へフォーカスし、エラー説明を関連づける。

## 5. シーン

シーンは、曲中のある時刻における静的な隊列表です。

基本仕様:

- `FormationFrame.timeSec` はシーン開始時刻。
- 再生中は、現在時刻以下で最も後ろのシーンを表示する。
- 次シーン開始時刻までは現在シーンの配置を維持する。
- シーン途中でメンバーや道具を勝手に補間移動させない。
- 非表示メンバーや非表示道具を次シーンから先取りして表示しない。
- シーン一覧・番号・前後移動は常に時刻順。同時刻は保存配列の順を保ち、表示用の並べ替えでは保存配列・共同編集データを変更しない。
- シーン詳細の時刻は入力中の値を保持し、blur／Enterで確定する。手動ドラッグ並べ替え・時刻順ボタンは表示しない。

シーン小窓:

- シーン小窓は固定サイズにする。
- シーン数が少なくても縦に引き伸ばさない。
- シーン数が多い場合は小窓リストだけスクロールする。
- 小窓内の表示は簡潔にし、シーン番号は数字中心にする。

## 6. メンバー

メンバーはステージまたはパレード上に配置できる隊列表の基本要素です。

主な仕様:

- メンバー名は円内に表示する。
- 長い名前は円内で2行表示を基本にする。
- メンバー色は個別色、グループ色、シーンごとの色上書きを扱う。
- シーンごとの色上書きは `memberAppearanceOverrides` で管理する。
- メンバー同士が完全に重なりすぎて見失わないようにする。
- 新規追加したメンバーは追加したシーンでは表示、その他のシーンでは自動で非表示にする。

## 7. 道具

道具は、幕、椅子、机、パネル、マーク、範囲、カスタムなどを含む配置要素です。

主な仕様:

- UI上は「道具」に統一し、幕も道具の種類として扱う。
- 道具グループを持つ。
- グループ所属道具はグループカード内だけに表示し、未所属一覧には重複表示しない。
- 表示切替リストは例外として全道具を表示してよい。
- 新規追加した道具は追加したシーンでは表示、その他のシーンでは自動で非表示にする。
- 道具のマウス移動はグリッド設定に従い、現在重視する移動単位は0.25m。

## 8. 道具割当

道具割当はシーンごとに管理します。

基本仕様:

- `FormationFrame.objectAssignments?: Record<objectId, memberId[]>`
- 道具別ビューとメンバー別ビューを持つ。
- 道具別ビューでは、そのシーンで表示中の道具だけを対象にする。
- 非表示道具は、そのシーンで使わないため割当対象に出さない。
- 割当メンバーは、そのシーンでは隊列外として扱う。
- メンバータブ非表示側には `割当: 道具名` を表示する。
- メンバー別ビューでは「道具」と「非表示」だけを表示し、「踊り」「出番」は表示しない。
- 道具表示順はグループごとにまとまるようにする。
- 直前シーンで同じ道具が表示中の場合、ワンクリックで割当を引き継げるようにする。

## 9. 選択対象の座標カード

- 詳細タブは設けず、メンバー・道具タブの通常見出し・操作の下、このシーンの表示の上に座標カードを表示する。縦画面でも上部に置く。
- 単独選択のメンバーは名前と色、横・縦位置を表示する。複数選択では人数だけ表示する。
- 道具は名前と横・縦・幅・高さ・回転を表示し、寸法・回転の編集欄はこのカードに集約する。最小寸法0.01mと、寸法変更時の位置補正を維持する。
- 既存の座標変換、センター割りの左右表示、実効シーン寸法、パレードの後方距離を維持する。数値入力に吸着を適用しない。
- 再生中・閲覧のみでは入力を無効にする。変更は既存Undo経路で保存する。
- Ctrl/Cmd+1は選択対象のタブを開いてカードへフォーカスする。未選択ならメンバータブを開く。
- 座標の見方・ショートカットは使い方に掲載する。previewモードと保存済みanimationSettingsは維持する。

## 10. 保存と共有ファイル

保存:

- collaborationV2有効時、未共有の隊列表のホーム「…」からクラウドに保存できる。恒久アカウントへのログインが必要で、ログイン後に自動実行しない。対象ID・操作世代を固定して開き、既存の共有開始処理を利用する。招待・管理画面は開かず、招待発行も行わない。成功後は編集画面にとどまる。旧本人クラウド同期中の隊列表は複製して保存する。
- 隊列表データはWeb/WindowsではIndexedDB、iPadアプリではネイティブSQLite Repositoryへ1件単位で保存する。
- 起動時に旧データを移行し、旧localStorage・iPadミラーは読み取り専用で残す。本人クラウドの下書きファイルは別経路を維持する。
- 音源ファイル本体は端末のみへ保存する。Web/WindowsはIndexedDBのBlob、iPadネイティブはApplication Support内のファイルを使い、IDから解決したURLで再生する。旧iPad音源はコピー移行し、元ファイルを残す。
- 隊列表データ側には音源メタ情報を保存する。
- 復元候補・検証済み端末バックアップからの復旧、手動全件バックアップ、音源GC、利用者による旧データ整理を提供する。安全条件と未確認項目は `docs/STORAGE_RECOVERY_BACKUP.md` を参照する。

共有ファイル:

- サーバー不要のファイル共有を基本にする。
- ZIP形式で書き出し・読み込みする。
- `.tairetsu` と `.zip` の読み込みをサポートする。
- LINEやiPad経由でMIME typeや拡張子が変わっても、最終的にはZIP内部の `manifest.json` と `project.json` で判定する。
- ZIP内部ファイル名はASCII固定名にする。
- 共有リンク機能は使わない方針。
- JSON単体バックアップは優先度低め。

読み込み判定:

- 拡張子やMIME typeだけで拒否しない。
- `.tairetsu`、`.zip`、`application/octet-stream`、MIME type不明のファイルでも、ZIPとして展開できれば検証する。
- 最終判定は `manifest.json` と `project.json` の存在、`fileType`、`formatVersion` で行う。
- 不正ファイルではアプリを落とさず、分かりやすいエラーを出す。

## 11. 印刷

印刷機能は、アプリ画面全体ではなく隊列表そのものを出力することを目的にします。

現在重視する仕様:

- 各シーンのステージ画像とシーン名だけを出力する。
- 時間情報、メモ欄、操作UI、デバッグ表示は出さない。
- 全シーンを縦に並べる。
- 適切な余白を入れ、グリッドの連続感を保つ。
- 印刷/PDF保存しやすいレイアウトにする。
- 既存の編集画面UIは印刷に含めない。
- 印刷対象はステージグリッド、メートル目盛り、センターライン、メンバー、道具、幕、ステージ枠線を基本にする。
- 選択枠、リサイズハンドル、右クリックメニュー、ツールバーは含めない。
- 全シーンを縦に並べる場合、ページ分割が自然になるようにする。

閲覧用の書き出し:

- 隊列表はA4だけとし、「このシーン／全シーン」と形式「PDF／画像」を選べる。道具割当欄の有無を両形式で選べる。
- A4 PDFの既存ページ分割・描画・用紙・20ptの余白・中央への収まり方を維持する。
- A4画像は各 `.print-page` を1枚ずつ2倍で描画し、PDFと同じ用紙・余白・収まり方の白いA4へ約192dpiで配置する。Canvas→Blobをページ順に逐次処理し、各Canvasを解放する。全ページを縦長Canvasにしない。
- 画像名は `演目_隊列表_日時_001.png`。ページ連番は最低3桁で、総数の桁数に合わせる。複数枚には画像内にも `1/12` のようなページ番号を付ける。1枚の場合は画像内番号を省く。
- 共有シートへ渡す画像配列とWeb完了画面の個別保存ボタンはページ順を維持する。写真アプリ保存後の並びは保証範囲外。
- メンバー名簿はスマホ向け・A4のPDF／画像を維持する。道具名簿と道具割当表（スマホ用）の書き出しは廃止する。登録・管理・割当編集・保存データ・A4隊列表の割当欄は維持する。
- スマホ向け隊列表の専用出力経路は削除する。名簿割当画面やサムネイル等が使う静的描画・範囲計算は維持する。
- ZIP・バックアップは再編集用であり、PDF／画像選択の対象外。

## 12. スクリーンショット

ステージ周辺だけを画像またはPDFにする機能です。ステージのカメラとパレード左側の画像保存で形式を選べます。PDFは既存画像の余白・縦横比を維持し、追加余白のない1ページに配置します。

含めるもの:

- ステージグリッド
- 上メモリ数字
- 左メモリ数字
- メンバー
- 道具
- 幕
- センターライン
- ステージ枠線

含めないもの:

- 左パネル
- シーン一覧
- 再生バー
- 上部操作ボタン
- カメラボタン自身
- 選択枠
- リサイズハンドル
- ホバーUI

PCでは保存とクリップボードコピー、iPadでは共有シートやプレビューなど、Webブラウザの制約内で最も使いやすい方法へフォールバックします。

実装方針:

- 画面全体ではなく、ステージ表示に必要な範囲だけを対象にする。
- メートル数字が切れないよう、上・左・右・下に適度な余白を含める。
- 選択枠、リサイズハンドル、ホバーUI、操作ボタンは一時的に非表示にする。
- 高解像度でもぼやけにくいようにする。

## 13. UI方針

- 白背景、薄いグレー境界線、緑系アクセントを基本にする。
- 操作ボタンは分かりやすく整理する。
- ステージやパレードキャンバスの表示領域を優先する。
- 画面上部に操作を詰め込みすぎない。
- パレードモードでは操作パネルを隊列表左側へ置き、右側を隊列表表示に使う。
- iPad横向きでも操作パネルが上部に戻りすぎないようにする。
- 横画面のメンバー・道具タブは、通常の見出し・操作、選択対象の座標カード、このシーンの表示、固定する表示／非表示切替と追加先、管理一覧の順に置く。縦画面の管理対象切替はグループ一覧の見出しに維持する。
- パレードの画像保存・拡大縮小ロック・全画面は操作パネル上部へまとめる。「スタートへ」「ゴールへ」「100%」ボタンは表示せず、ピンチ／ホイールによる拡大縮小は維持する。
- パレードの前シーン反映は「全員」またはグループを1つの対象選択で指定し、移動量0の反映と反映して移動の両方で使う。指定グループの削除時は全員へ戻す。
- パレード操作の見出し付近に、表示中かつ道具に割り当てられていないメンバーの有限な中心Yの最小値から求めた「最前 ○○m」を表示する。対象がなければ「最前 —」。画像保存には含めない。
- UI文言は日本語で統一する。
- ボタンが多い場合は、表示領域を削らない場所へ移動する。
- 文字がなくても意味が通る操作はアイコン中心にしてよいが、アクセシビリティ用の `title` と `aria-label` は残す。
- ステージモードとパレードモードで同じUIに見えても、目的が違う場合は挙動を分ける。

## 14. 変更時の確認方針

実装後は、変更内容に応じて以下を確認します。

共通:

- `npm run build` が成功する。
- `git status --short` で意図しない差分がない。
- 既存の保存データを読み込んでもエラーにならない。

ステージモード:

- 新規作成できる。
- メンバー・道具を配置、移動、表示/非表示できる。
- センターから1m刻みとセンターから0.5mずらしが既存仕様どおりに見える。
- フルスクリーンが既存どおり動く。

パレードモード:

- 縦長キャンバスをスクロールできる。
- ピンチ／ホイールによるズーム、拡大縮小ロック、フルスクリーンが役割どおり動く。
- 左右のm目盛り、5m/10mラインがずれない。
- 操作ボタン群が隊列表左側にまとまっている。
- センターから1m刻みとセンターから0.5mずらしがステージモード仕様に揃っている。

印刷・スクリーンショット・ZIP:

- 印刷にはシーン名とステージ画像だけが出る。
- スクリーンショットにはステージ周辺だけが写る。
- `.zip` / `.tairetsu` を読み込める。
- 音源あり/なしの共有ファイルで破綻しない。

## 15. 今後の実装方針

優先すること:

- 既存のステージモードを壊さず安定させる。
- パレードモードを縦長隊列に適したUIへ整える。
- スクリーンショット・印刷の品質を上げる。
- ZIP読み込み・書き出しの安定性を上げる。
- 座標カードでの編集体験を整える。

優先度が低いもの:

- 共有リンク機能
- JSON単体バックアップ
- シーン間の自動アニメーション
- 複雑な共同編集

実装時は、変更範囲を小さく保ち、ステージモードとパレードモードの分岐を明確にしてください。

大規模変更では、型定義、保存互換性、UI、印刷/スクリーンショット、ビルド確認の順に段階的に進めます。
