# iPadOS 27対応と改善調査

## 範囲と結論

2026-09-24。音源取り込み、保存、共有書き出し、iOS起動設定、CIをコードで確認した初回調査。全機能監査やiPadOS 27実機検証の完了を意味しない。Web版の共同編集とiPad版の個人クラウド保存の区分、保存形式は変更しない。今回は公開・TestFlight配信を行わない。

## 今回修正した不具合

対象: `src/platform/audioPicker.ts`、同テスト。

- 非対応拡張子、既知の空ファイル、不正なサイズを、ファイル全体のfetch/blob読み込み前に拒否する。既存の200MB上限も同じ経路で検査する。
- URIがあるが名前が取得できない場合にも、一時ファイルを回収する。
- 読み込み失敗時の回収、回収失敗時にも正常な取り込み結果を維持する動作をテストする。
- 取得後の実サイズ検証も残す。Swift側のコピー自体を省く修正ではない。

検証: 対象テスト11件成功、`npm run build`成功（TypeScriptチェックを含む）。ネイティブプラグインはモックであり、実機のファイル選択やメモリ使用量は未検証。

## iPadOS 27で確認すべき事項

Appleは最新SDKでビルドするiOS/iPadOS 27向けアプリにSceneベースのライフサイクルを求めている。既存バイナリが一律に起動不能になるという意味ではない。

出典: https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle

現コードにはInfo.plistのUIApplicationSceneManifestとSceneDelegateが存在し、起動時のウィンドウ生成およびURL受け渡しが実装されている。この移行をゼロから行う必要はない。ただし起動成功を実機で検証したわけではない。

次回の検証対象:

1. iPadOS 27で新規起動、バックグラウンド復帰、ログインからアプリへの復帰。
2. 縦横回転、ウィンドウサイズ変更、Stage Manager、キーボード表示中の入力欄とキャンバス位置。
3. 音源をファイル/iCloudから選択、キャンセル、再生、非対応音源の拒否。
4. ローカル保存後の再起動、オフライン編集から復帰、個人クラウド保存・読み込み。
5. PNG/PDF/ZIPの保存・共有とキャンセル。ステージ/パレード双方、大きい隊列でも確認。

最低対応OSを27に引き上げたり、OS更新だけを理由に全画面をネイティブ化したりはしない。

## 次の改善候補（優先順）

### 1. 保存結果と復元の可視化

`src/utils/storage.ts`にはlocalStorage保存、`src/platform/projectStorage.ts`にはネイティブミラーの書き込みキューとpending/backupからの復元がある。バックグラウンド移行時の保存もApp.tsxに存在する。

一方、ミラー保存は非同期で、失敗はconsole.warnに流れる。ローカル保存成功と端末バックアップ成功を区別して表示し、容量不足時の再試行・ZIP退避導線を検討する。現段階でデータ消失を再現したわけではない。保存状態を誤って一括成功扱いしないテストを先に設ける。

### 2. 大容量音源・書き出しのメモリ対策

SwiftのAudioDocumentPickerPluginはコピー後にサイズを取得する。コピー前の上限チェック、コピー処理のバックグラウンド化を検討する。iCloud取得中の扱い、キャンセル、完了コールバックが一度だけ呼ばれることをセットで検証する。

`src/platform/files.ts`の共有はBlobをbase64化してCacheへ書くため、大きなPDF/ZIPでは一時的に複数のデータ表現を保持する。実機でメモリを測定し、必要ならファイルベースの経路に移す。無条件な上限引き下げはしない。

### 3. CIをビルド確認から操作確認へ

`.github/workflows/ios-build.yml`はSimulator向けReleaseビルドまでで、Simulator起動後の操作テストではない。Xcode/SDKのバージョンを記録・固定し、利用可能なiPadOS 27ランタイムで起動・復帰・読み込みのスモークテストを追加する。Windows上の今回のWebビルドをiOSネイティブビルド成功とは扱わない。

### 4. 可変サイズUIを重点検証

縦持ちの上下配置という既存方針を維持する。固定vhの存在だけで不具合とは断定せず、キーボード表示や狭いウィンドウで実測してから、visual viewportやsafe-areaの扱いを局所修正する。iPadOS 27固有のズーム不具合は今回再現していない。

### 5. 大規模データでの性能と保守性

全プロジェクトのJSON化・localStorage書き込み時間、キャンバス操作時の再描画、書き出しピークメモリを測る。App.tsxの分割は保存、クラウド、画面構成など責務ごとに回帰テストとセットで行う。単なるファイル分割を高速化と混同しない。

## 推奨する次の一単位

まず保存状態の可視化と失敗時の復元導線を設計・実装し、それと並行してiPadOS 27実機確認表を埋める。AIによる隊列自動生成など新機能の前に、作業を失わないことと安定した操作を優先する。
